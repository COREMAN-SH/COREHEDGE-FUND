# 코인 카테고리 · 펀더멘탈 체계

> **왜 이 문서가 필요한가:** L1 체인과 DEX 토큰과 오라클 토큰을 같은 잣대로 보면 반드시 틀린다.
> 카테고리마다 **무엇이 펀더멘탈인지가 다르다.** 이 문서는 그 대응표다.
> 최종 갱신: 2026-09-09

---

## 1. 분류는 3개 축으로 한다

하나의 축으로 줄 세우면 정보가 뭉개진다. 세 축을 독립적으로 매긴다.

```
축 A. 기능 유형   — 무엇을 하는 프로젝트인가        → 어떤 지표를 볼지 결정
축 B. 가치 포착   — 토큰에 가치가 어떻게 흘러가는가  → 성장이 가격에 반영되는지 결정
축 C. 시장 티어   — 시총·유동성 규모               → 포지션 사이징·리스크 결정
```

**축 A가 "무엇을 측정할지"를 정하고, 축 B가 "그 측정치가 의미가 있는지"를 정한다.**
축 A만 보고 판단하는 것이 가장 흔한 실수다 — 사용량이 늘어도 축 B가 없으면 가격과 무관하다. → [[../foundations/02-value-on-chain|가치 포착 문서]]

---

## 2. 축 A — 기능 유형과 그에 따른 핵심 지표

### A-1. 범용 L1 (스마트컨트랙트 플랫폼)
**해당:** ETH, SOL, ADA, SUI, NEAR, AVAX, BNB
**본질:** 블록스페이스를 파는 사업. 수요는 개발자·사용자가 만든다.

| 반드시 확인 | 왜 |
|---|---|
| 수수료 수익 (일·월) | 블록스페이스에 대한 **실제 지불 의사** |
| 활성 주소 / 트랜잭션 수 | 수요의 폭. 단 봇·에어드랍 파밍 오염 주의 |
| TVL (**네이티브 수량 기준**) | 자본이 상주하는가. USD 기준은 가격에 종속됨 |
| 스테이킹 비율 | 유통 물량 잠김 + 보안 예산 |
| 검증자 수 · 지분 집중도 · 클라이언트 다양성 | 탈중앙성의 실질. 장애 리스크 |
| 인플레이션율 vs 소각량 | **순공급 변화**가 음수인가 |
| 네트워크 장애 이력 | 신뢰성. SOL의 반복 장애가 대표 사례 |

**⚠️ 카테고리 특유의 함정**
- **L2로 활동이 이전되면 L1 지표가 구조적으로 하락한다.** ETH의 소각량 급감(하루 수천 → 50~70 ETH)이 정확히 이 현상이다. "사용량 감소"가 아니라 "측정 위치 이동"일 수 있다
- 무료·초저가 체인(SOL 등)의 트랜잭션 수는 타 체인과 **비교 불가**다

---

### A-2. 저장 수단 / 통화형
**해당:** BTC, LTC
**본질:** 현금흐름이 없다. **화폐적 프리미엄**이 가치의 전부에 가깝다.

| 반드시 확인 | 왜 |
|---|---|
| 채택 지표 (ETF 순유출입, 기업·국부펀드 보유) | 새로운 수요 주체가 들어오는가 |
| 보유자 행동 (LTH 공급, SOPR, 코인일수파괴) | 기존 보유자가 파는가 버티는가 |
| 해시레이트 · 난이도 · 채굴자 매출 | 보안 예산의 건전성 |
| 수수료가 채굴자 매출에서 차지하는 비중 | **장기 보안 예산 문제**의 핵심 수치 |
| 거시 상관관계 (실질금리, DXY, 유동성) | 이 카테고리는 매크로 자산에 가깝다 |

**⚠️ 함정**
- **P/E, 매출 배수로 평가하려는 시도는 범주 오류다.** DCF를 쓸 수 없다
- 반감기 직후 Puell Multiple이 인위적으로 낮게 나온다(분모가 365일 MA라서). 이 구간의 저값은 매수 신호가 아니다

---

### A-3. DeFi 애플리케이션
**해당:** UNI
**본질:** 수수료를 버는 사업. **가장 주식에 가깝게 평가할 수 있는 카테고리.**

| 반드시 확인 | 왜 |
|---|---|
| 프로토콜 수수료 (연환산) | 매출 |
| **실질 매출** = 수수료 − 토큰 인센티브 배출 | 음수면 사용량을 보조금으로 산 것 |
| P/F = FDV / 연환산 수수료 | 동종 비교용 배수 |
| 시장 점유율 추이 | 경쟁 압력 |
| 소각량 vs 신규 발행 | **순 디플레이션 여부** |
| 사용자 수·거래량의 출처 | 인센티브 파밍인가 실수요인가 |

**⚠️ 함정**
- TVL은 예치 자산 가격에 종속된다. 반드시 네이티브 수량 병행
- 워시 트레이딩·파밍 유인 거래가 수수료를 부풀린다
- UNI 사례: 소각 1억 개를 발표하고도 시장 상황에 눌려 사이클 저점을 기록했다. **좋은 뉴스가 매크로를 이기지 못한다**

---

### A-4. 인프라 / 미들웨어
**해당:** LINK (오라클)
**본질:** 다른 프로토콜에 서비스를 판다. B2B에 가깝다.

| 반드시 확인 | 왜 |
|---|---|
| TVS (Total Value Secured) | 이 인프라에 의존하는 자산 규모 |
| 통합 프로토콜·체인 수 | 채택의 폭 |
| **결제 수단이 무엇인가** | ⚠️ **이 카테고리 최대 쟁점** |
| 경쟁자 점유율 | Pyth 등의 잠식 |
| 기관 파이프라인의 상용화 전환율 | 파일럿과 매출은 다르다 |

**⚠️ 함정 (이 카테고리의 구조적 약점)**
- **사용량 ↑ 가 토큰 수요 ↑ 로 직결되지 않는 대표 사례.** 오라클 이용료를 스테이블코인으로도 낼 수 있으면 LINK를 살 이유가 없다
- "SWIFT와 협업"류 뉴스는 **파일럿**인 경우가 많다. 실제 매출 계상 여부를 분리해서 봐야 한다

---

### A-5. RWA / 토큰화
**해당:** ONDO
**본질:** 전통금융 자산을 온체인에 올린다. **평가 기준이 절반은 전통금융 쪽이다.**

| 반드시 확인 | 왜 |
|---|---|
| AUM (운용 자산) 및 증감 | 사업 규모 |
| 규제 라이선스 (브로커-딜러, ATS 등) | 진입장벽이자 필수 조건 |
| 법적 래퍼 구조 (SPV/신탁), 도산격리 | → [[../foundations/03-tokenized-securities\|03번 문서]] 4장 |
| 상환(redemption) 경로 | 실제로 빠져나올 수 있는가 |
| 커스터디언과 감사 | 자산이 진짜 있는가 |
| **수수료가 토큰 보유자에게 가는 경로** | 대부분 없다 |

**⚠️ 함정**
- **"RWA 시장이 커진다 → RWA 토큰이 오른다"는 성립하지 않는다.** ONDO가 토큰화 주식 점유율 1위인데 토큰 가격은 장기 하락추세선 아래다
- 지배구조 리스크가 이례적으로 크다(ONDO 델라웨어 소송). 전통금융 자산을 다루면 법인 거버넌스가 곧 리스크가 된다

---

### A-6. 프라이버시
**해당:** ZEC
**본질:** 규제와 정면으로 부딪히는 카테고리. **기술보다 규제가 지배 변수.**

| 반드시 확인 | 왜 |
|---|---|
| **쉴디드(보호) 풀 비중** | 이 카테고리의 유일한 진짜 실사용 지표 |
| 거래소 상장·상장폐지 동향 | 유동성의 생사 |
| 규제 일정 (EU AMLR 등) | 구조적 리스크의 시간표 |
| ETF·기관 접근 경로 | 규제 압박의 반대편 |

**⚠️ 함정**
- 프라이버시가 **기본값이 아니면** 실효성이 크게 떨어진다. 투명 주소와 쉴디드 주소가 공존하는 구조의 근본 한계
- 규제 리스크는 되돌리기 어렵다. 한 번 상장폐지되면 복귀가 잘 안 된다

---

### A-7. 인터체인 / 상호운용성
**해당:** ATOM
**본질:** 체인을 연결한다. **가치 포착 실패의 교과서적 사례가 많다.**

| 반드시 확인 | 왜 |
|---|---|
| 연결 체인 수 · IBC 트래픽 | 기술 채택 |
| **허브 토큰의 필수성** | ⚠️ 연결된 체인들이 자기 토큰을 쓰면 허브 토큰 수요는 0 |
| 토크노믹스 개편 진행 상황 | 이 카테고리의 유일한 반전 경로 |
| 생태계 보안 사고 | 연결성이 곧 전염 경로다 |

**⚠️ 함정**
- 생태계 성장과 토큰 가치가 **구조적으로 분리**되어 있다. 개편이 거버넌스를 통과하고 **실제 시행**될 때까지는 서사일 뿐이다
- 연결된 체인 하나가 털리면 생태계 전체 신뢰가 흔들린다 (Cosmos EVM 취약점 사례)

---

### A-8. 신원 / AI 인프라
**해당:** WLD, (NEAR의 AI 축)
**본질:** 서사가 강하고 검증이 어렵다. **가장 조심해야 할 카테고리.**

| 반드시 확인 | 왜 |
|---|---|
| 인증 사용자 수 · 실제 호출량 | 서사가 아닌 실사용 |
| 파트너십의 **연동 사용자 수** | 발표와 실사용은 다르다 |
| 국가별 규제 상태 (금지/조사/허용) | 확장 가능 시장의 실제 크기 |
| 언락 스케줄 | 이 카테고리는 대체로 잠긴 물량이 많다 |

**⚠️ 함정**
- **파트너십 발표는 지표가 아니다.** "Tinder·Zoom과 제휴"에서 실제 연동 사용자 수로 넘어가는지 확인해야 한다
- 서사 의존도가 높으면 서사가 식을 때 하방이 깊다

## 3. 축 B — 가치 포착 메커니즘

각 코인이 **네 가지 중 무엇을 쓰는지** 표시한다. 없으면 없다고 적는다.

| 메커니즘 | 확인 방법 | 검증 질문 |
|---|---|---|
| **소각** | 온체인 소각 주소 누적량 | 신규 발행과 상계했을 때 순공급이 음수인가 |
| **스테이킹 락업** | 스테이킹 비율 | 보상이 신규 발행이면 실질 수익률 = 명목 − 인플레 |
| **수수료 배분** | 분배 컨트랙트 | 규제 위험은 어떻게 관리하는가 |
| **사용 필수성** | 가스·담보 요구 | **대체 결제 수단이 있는가** ← 가장 중요 |

**표기 규칙:** 각 코인 노트 3번 섹션 첫 줄에 다음 형식으로 명시한다.

```
> 가치 포착: 소각(오토번, 분기) + 사용 필수성(BSC 가스) | 순공급: 감소
> 가치 포착: 없음 — 거버넌스 전용 | 순공급: 증가(인플레 2.5%)
```

## 4. 축 C — 시장 티어

| 티어 | 기준 | 포지션 원칙 |
|---|---|---|
| 메이저 | BTC, ETH | 코어. 매크로 자산으로 취급 |
| 마이너 대형알트 | BNB, SOL | 준코어. 유동성 충분 |
| 마이너 일반 | 나머지 | 위성. **개별 스토리보다 사이클 베타가 지배** |

> **집중도 경고:** 15개를 보유해도 실질 독립 리스크 요인은 사실상 하나다 — **달러 유동성에 연동된 크립토 사이클 베타.** 분산되어 보이지만 분산이 아니다

## 5. 코인별 매핑 (2026-09-09)

| 코인 | A 기능 | B 가치 포착 | C 티어 |
|---|---|---|---|
| BTC | 저장 수단 | 사용 필수성(약) / 화폐적 프리미엄 중심 | 메이저 |
| ETH | 범용 L1 | 소각 + 스테이킹 락업 (순공급 **증가**) | 메이저 |
| BNB | 범용 L1 + 거래소 | 소각(분기) + 사용 필수성 (순공급 **감소**) | 대형알트 |
| SOL | 범용 L1 | 스테이킹 락업 + 부분 소각 (인플레 3.84%) | 대형알트 |
| ADA | 범용 L1 | 스테이킹 락업 (인플레 약 2%) | 마이너 |
| SUI | 범용 L1 | 스토리지 펀드 잠김 + 스테이킹 | 마이너 |
| NEAR | 범용 L1 (AI) | 소각 70% + Intents 수수료 100% 매수 | 마이너 |
| AVAX | 커스터마이즈 L1 | 수수료 **전액 소각** ⚠️ L1 자체 가스토큰 사용 시 희석 | 마이너 |
| LTC | 저장/결제 | 없음에 가까움 | 마이너 |
| UNI | DeFi 앱 | 소각(Firepit) ⚠️ 그로스 예산이 상쇄 | 마이너 |
| LINK | 인프라(오라클) | ⚠️ **취약** — 대체 결제 수단 존재 | 마이너 |
| ONDO | RWA | ⚠️ **취약** — 상품 수수료가 토큰에 안 감 | 마이너 |
| ATOM | 인터체인 | ⚠️ **실패** — 개편 진행 중 | 마이너 |
| ZEC | 프라이버시 | 없음 (BTC형 희소성) | 마이너 |
| WLD | 신원/AI | 없음 ⚠️ 언락 부담 최대 (MC/FDV 0.36) | 마이너 |

> **한눈에:** 15개 중 **가치 포착이 명확히 작동하는 것은 BNB, NEAR, UNI 정도**다. 나머지는 화폐적 프리미엄형이거나 가치 포착이 취약하다. 이 사실이 포트폴리오 논거의 출발점이 되어야 한다

## 6. 노트 작성 시 적용 규칙

1. 노트 최상단에 **축 A / 축 B / 축 C** 를 한 줄로 표기한다
2. 5번 시장현황에는 **축 A의 "반드시 확인" 지표**를 우선 배치한다
3. 7번 투자관점의 약세 논거에는 **해당 카테고리의 "함정"** 을 반드시 포함한다
4. 무효화 조건(thesis invalidation)을 **수치로** 적는다. "악화되면"이 아니라 "X가 Y 아래로 내려가면"
