# 04. 비트코인의 원리

> [[01-blockchain-basics|01번 문서]]가 부품을 설명했다면, 이 문서는 **그 부품들이 실제로 어떻게 조립되어 있는지** 본다.
> 비트코인은 블록체인의 첫 구현이자, 지금도 가장 단순하고 가장 검증된 구현이다.

---

## 1. 비트코인이 발명한 것과 발명하지 않은 것

2008년 사토시 나카모토의 논문에 쓰인 기술 대부분은 **이미 존재하던 것**이다.

| 요소 | 언제부터 있었나 |
|---|---|
| 공개키 암호 · 전자서명 | 1970년대 |
| 해시 함수 | 1970~90년대 |
| 작업증명(PoW) | 1997년 해시캐시 (스팸 방지용) |
| 해시로 엮은 타임스탬프 체인 | 1991년 |
| 분산 시스템 합의 이론 | 1980년대 (비잔틴 장군 문제) |

**비트코인의 진짜 발명은 이 조합이다.**

> **경제적 인센티브를 합의 규칙 안에 넣어서, 정직한 행동이 공격보다 이득이 되게 만든 것.**

기존 분산 합의 연구는 "참여자가 누구인지 미리 아는" 환경을 가정했다. 비트코인은 **누구나 익명으로 들어오고 나갈 수 있는 환경**에서 합의를 이뤘다. 그 대가로 낸 것이 전기다.

## 2. 키와 주소 — 소유권은 무엇으로 증명되는가

### 2-1. 세 단계

```
개인키(Private Key)  →  공개키(Public Key)  →  주소(Address)
     비밀              공개해도 안전            받을 때 알려주는 것
```

**개인키의 실체는 그냥 256비트 난수다.** 다른 말로 0부터 2²⁵⁶−1 사이의 정수 하나.

```
개인키 예시(16진수 64자리):
E9873D79C6D87DC0FB6A5778633389F4453213303DA61F20BD67FC233AA33262
```

이 숫자에서 **타원곡선 곱셈**(secp256k1 곡선)으로 공개키를 만든다. 이 연산은 **단방향**이다 — 개인키에서 공개키는 쉽게 계산되지만, 공개키에서 개인키는 역산할 수 없다.

공개키를 해시(SHA-256 → RIPEMD-160)하면 주소가 된다.

### 2-2. 2²⁵⁶이 얼마나 큰 수인가

"남의 개인키를 무작위로 맞힐 수 있지 않나"라는 질문이 자연스럽게 나온다. 숫자로 보자.

```
2²⁵⁶ ≈ 1.16 × 10⁷⁷

관측 가능한 우주의 원자 수 ≈ 10⁸⁰
```

**개인키 공간이 우주 전체 원자 수의 1/1000 수준이다.** 지구상 모든 컴퓨터를 우주 나이만큼 돌려도 하나 맞힐 확률이 사실상 0이다.

> 그래서 비트코인이 털리는 사건은 **암호가 깨져서**가 아니라, 개인키가 든 파일이 유출되거나 거래소가 해킹당하거나 사용자가 피싱당해서 일어난다. **1장에서 본 "체인은 안전한데 주변부가 털린다"는 패턴**이 그대로다.

### 2-3. 서명

돈을 보낼 때 개인키로 거래 내용에 **서명**한다. 네트워크는 공개키로 그 서명이 유효한지 검증한다.

```
검증되는 것: "이 거래는 해당 주소의 개인키를 가진 사람이 만들었다"
             + "거래 내용이 서명 후 변경되지 않았다"
```

**개인키는 절대 네트워크에 전송되지 않는다.** 이게 "Not your keys, not your coins"라는 말의 기술적 근거다.

## 3. UTXO — 잔액이 아니라 "받은 수표 뭉치"

이더리움과 비트코인의 가장 큰 구조적 차이다. 이걸 이해해야 온체인 데이터도 제대로 읽힌다.

### 3-1. 은행 방식 (계정 모델)

```
계좌 잔액: 5.0 BTC     ← 숫자 하나
3 BTC 송금 → 잔액 2.0 BTC로 수정
```

### 3-2. 비트코인 방식 (UTXO 모델)

비트코인에는 "잔액"이라는 필드가 **없다.** 대신 **아직 쓰지 않은 출력값(UTXO, Unspent Transaction Output)** 들의 목록이 있다.

지갑이 "5 BTC 보유"라고 표시하는 것은, 실제로는 이런 상태다.

```
내 주소가 가진 UTXO들:
  UTXO-A:  2.0 BTC   (2026년 3월에 받음)
  UTXO-B:  1.5 BTC   (2026년 6월에 받음)
  UTXO-C:  1.5 BTC   (2026년 8월에 받음)
  ─────────────────
  합계     5.0 BTC   ← 지갑이 더해서 보여주는 것
```

**수표 뭉치라고 생각하면 정확하다.** 각 수표는 통째로만 쓸 수 있다.

### 3-3. 3 BTC를 보낼 때 실제로 일어나는 일

```
[입력]  UTXO-A (2.0) + UTXO-B (1.5)  = 3.5 BTC   ← 두 수표를 소각
   ↓
[출력]  상대방에게      3.0 BTC       ← 새 UTXO 생성
        나에게(거스름돈) 0.4999 BTC   ← 새 UTXO 생성
   ↓
[수수료] 3.5 − 3.4999 = 0.0001 BTC   ← 채굴자가 가져감
```

**중요한 세 가지**

1. **수수료는 따로 적는 필드가 아니다.** `입력 합계 − 출력 합계`가 자동으로 수수료가 된다. 거스름돈 출력을 빠뜨리면 **전액이 수수료로 날아간다**
2. **거스름돈은 보통 새 주소로 간다.** 그래서 한 사람이 계속 새 주소를 만들게 되고, 이게 온체인 분석을 어렵게 만든다
3. **UTXO가 이동하면 "마지막 이동 시점"이 갱신된다.** [[../onchain/metrics-glossary|온체인 지표]]의 실현시총·SOPR·코인일수파괴(CDD)가 전부 이 성질 위에 세워져 있다

> **왜 이 방식을 썼나:** 병렬 검증에 유리하고(서로 다른 UTXO는 동시 처리 가능), 잔액 상태를 전역으로 관리할 필요가 없어 단순하다. 대신 스마트컨트랙트를 짜기는 훨씬 어렵다 — 이더리움이 계정 모델을 택한 이유다

## 4. 채굴 — 10분마다 벌어지는 일

### 4-1. 채굴자가 하는 일 (순서대로)

```
1. 네트워크에 떠도는 미확인 거래들을 수집 (멤풀)
2. 수수료가 높은 순으로 골라 블록에 담음 (약 1MB 한도)
3. 맨 앞에 "코인베이스 거래"를 넣음 — 자기에게 신규 발행 + 수수료 지급
4. 논스를 바꿔가며 블록 해시를 계산
5. 해시가 목표값보다 작아질 때까지 반복 (초당 수십조 회)
6. 찾으면 즉시 전파 → 다른 노드들이 검증 → 체인에 추가
```

### 4-2. 난이도 조정 — 자동 온도조절기

```
목표: 블록 하나당 평균 10분
조정: 2,016블록마다 (= 정확히 10분 간격이면 2주)

실제 소요 시간 < 2주  →  난이도 상향 (더 어렵게)
실제 소요 시간 > 2주  →  난이도 하향 (더 쉽게)
```

이 장치 덕분에 채굴기가 10배 늘어도, 절반이 나가떨어져도, **블록 간격은 10분 근처로 되돌아온다.** 발행 스케줄이 지켜지는 이유다.

> 2021년 중국 채굴 금지로 해시레이트가 급감했을 때도 난이도가 하향 조정되며 네트워크는 정상 작동했다. 설계의 견고함을 보여준 사례로 자주 인용된다

### 4-3. 왜 하필 10분인가

트레이드오프다. 너무 짧으면 전 세계 노드에 블록이 다 퍼지기 전에 다음 블록이 나와 **체인이 자주 갈라진다(고아 블록)**. 너무 길면 확인이 느려진다. 10분은 전파 지연을 충분히 흡수하는 보수적 선택이다.

## 5. 2,100만 개는 어디서 나온 숫자인가

계산해보면 임의의 숫자가 아니라 **규칙의 결과**임을 알 수 있다.

```
규칙: 210,000블록마다 블록 보상 반감

1기: 210,000 × 50      BTC = 10,500,000
2기: 210,000 × 25      BTC =  5,250,000
3기: 210,000 × 12.5    BTC =  2,625,000
4기: 210,000 × 6.25    BTC =  1,312,500
5기: 210,000 × 3.125   BTC =    656,250   ← 2024년 4월~ 현재
6기: 210,000 × 1.5625  BTC =    328,125   ← 2028년경~
...무한히 반감...
─────────────────────────────────────
합계 → 21,000,000 에 수렴
```

등비수열의 합이다. 첫 4년치 10,500,000의 **정확히 2배**로 수렴한다.

**2026년 현재 상황** (→ [[../coins/major/BTC-bitcoin|BTC 노트]])

| 항목 | 값 |
|---|---|
| 유통량 | 약 2,004.7만 BTC (예정량의 약 95.5%) |
| 남은 채굴량 | 약 95.3만 BTC |
| 현재 블록 보상 | 3.125 BTC |
| 연간 신규 발행 | 약 16.4만 BTC |
| 다음 반감기 | 약 2028년 초 (블록 1,050,000) → 1.5625 BTC |
| 마지막 사토시 | 이론상 2140년경 |

> **직관:** 이미 95%가 나왔다. 앞으로 114년에 걸쳐 나머지 5%가 나온다. 신규 공급의 영향력은 이미 매우 작고, 앞으로 더 작아진다. **가격은 거의 전적으로 기존 보유자의 매도 의향과 신규 수요로 결정된다** — 온체인 분석에서 보유자 행동 지표(SOPR, LTH 공급)를 중시하는 이유다

## 6. 노드와 채굴자는 다르다 — 가장 흔한 오해

| | 채굴자 (Miner) | 풀노드 (Full Node) |
|---|---|---|
| 하는 일 | 새 블록을 **제안** | 규칙 위반 여부를 **검증** |
| 필요 장비 | ASIC, 대규모 전력 | 일반 PC + 디스크 |
| 권한 | 어떤 거래를 담을지 선택 | **규칙 위반 블록을 거부** |
| 수는 | 수천 (풀에 집중) | 수만 |

**결정적 포인트:**

> 채굴자가 아무리 연산력이 많아도, **규칙을 위반한 블록은 노드들이 거부한다.**
> 예를 들어 채굴자가 자기에게 100 BTC를 발행하는 블록을 만들면, 계산을 아무리 많이 해도 모든 노드가 그 블록을 버린다.

이것이 비트코인의 최종 권한이 **채굴자가 아니라 노드 운영자(= 사용자)** 에게 있는 이유다. 규칙 변경(하드포크)에 합의가 어려운 것도 같은 구조 때문이다.

## 7. 파이널리티 — 왜 "6컨펌"인가

비트코인의 최종성은 **확률적**이다. "확정"이라는 순간이 없고, 시간이 갈수록 뒤집힐 확률이 지수적으로 감소한다.

동시에 두 채굴자가 블록을 찾으면 체인이 잠시 갈라진다. 다음 블록이 어느 한쪽에 붙으면 그쪽이 길어지고, 짧은 쪽은 버려진다(**최장 체인 규칙** — 정확히는 누적 작업량이 가장 많은 체인).

```
컨펌 수    되돌려질 확률(대략)     관행적 용도
   0             높음              불가 (이중지불 가능)
   1             낮음              소액 결제
   3             매우 낮음          일반 거래
   6             무시 가능          거래소 입금 기준
```

**6컨펌 ≈ 약 60분.** 이 숫자는 수학적 필연이 아니라 **관행**이다. 사토시 논문의 확률 계산에서 유래해 업계 표준으로 굳었다.

> **대비:** PoS 체인들은 대부분 **결정적 파이널리티**를 제공한다. 예를 들어 [[../coins/large-alt/SOL-solana|솔라나]]는 Alpenglow 도입으로 파이널리티를 12.8초 → 100~150ms로 단축하는 것을 목표로 한다. "되돌릴 확률이 낮아진다"가 아니라 "되돌릴 수 없다"로 성격이 다르다

## 8. 51% 공격 — 할 수 있는 것과 없는 것

가장 오해가 많은 주제다. **연산력의 과반을 확보해도 할 수 없는 일이 훨씬 많다.**

| 할 수 **있는** 것 | 할 수 **없는** 것 |
|---|---|
| 자기 거래를 되돌리기 (이중지불) | 남의 코인 훔치기 — **개인키가 없다** |
| 특정 거래를 블록에 안 담기 (검열) | 없는 코인을 만들어내기 — **노드가 거부** |
| 다른 채굴자의 블록 무시하기 | 발행 규칙(2,100만 개) 바꾸기 |
| 짧은 구간의 체인 재조직 | 오래된 과거 블록 변조 — 재계산 비용이 비현실적 |

**경제적 억지력이 핵심이다.** 51%를 확보할 하드웨어·전기를 살 돈이면, 정직하게 채굴해서 버는 게 낫다. 게다가 공격이 성공하면 BTC 가격이 폭락해 **공격자가 보유한 장비와 코인의 가치도 같이 무너진다.**

> **단, 이 논리는 큰 체인에서만 성립한다.** 해시레이트가 작은 소형 PoW 코인들은 실제로 51% 공격을 여러 번 당했다. 해시레이트를 시간 단위로 빌릴 수 있는 시장이 존재하기 때문이다

## 9. 장기 과제: 보안 예산 문제

비트코인의 가장 진지한 구조적 논쟁이다.

```
채굴자 수익 = 블록 보상(신규 발행) + 거래 수수료
                   ↓ 4년마다 반감              ↓ 이게 커져야 함
```

**2026년 현재 수수료는 채굴자 매출의 1% 미만 수준이다.** (일부 집계로는 약 0.5%)

반감기가 계속되면 블록 보상은 0에 수렴한다. 그때 수수료 시장이 충분히 성숙하지 않으면 **해시레이트를 유지할 유인이 사라지고, 보안이 약화된다.**

**가능한 시나리오**

| 시나리오 | 논리 | 반론 |
|---|---|---|
| 수수료 시장 성숙 | 블록 공간이 희소해져 수수료가 오름 | 수수료가 오르면 사용자가 L2로 이탈 → L1 수수료 수요 감소 |
| 가격 상승이 상쇄 | BTC 가격이 오르면 같은 보상도 달러 가치가 큼 | 무한 상승 가정에 의존 |
| 발행 상한 변경 | 프로토콜을 바꿔 소액 발행 지속 | 2,100만 캡은 **정체성의 핵심** — 합의 거의 불가능 |

> 2026년 8월 커뮤니티에서 이 논쟁이 재점화됐다(BIP-110, 커버넌트, 양자내성 등). 답은 아직 없고, **BTC 약세 논거의 가장 진지한 축**이다 → [[../coins/major/BTC-bitcoin|BTC 노트]] 7번 섹션

## 10. 확장 시도들

| 방향 | 내용 | 상태 |
|---|---|---|
| **Segwit (2017)** | 서명 데이터를 분리해 블록 용량 실질 확대 | 적용 완료 |
| **Taproot (2021)** | 슈노어 서명 도입 — 다중서명을 단일 서명처럼 보이게, 프라이버시·효율 개선 | 적용 완료 |
| **Lightning Network** | 오프체인 결제 채널. 두 사람이 채널을 열고 그 안에서 무제한 거래 후, 최종 잔액만 온체인에 기록 | 운영 중 |
| **커버넌트(Covenant)** | OP_CTV, OP_CAT 등 — "이 코인은 이런 조건으로만 쓸 수 있다"를 강제. 비신뢰 볼트, 배치 처리 가능 | **논쟁 중** |

**라이트닝의 원리 (간단히)**

```
1. A와 B가 온체인에 채널을 연다 (각자 1 BTC 예치)
2. 채널 안에서 잔액 배분을 서로 서명해가며 무제한 교환 — 온체인 기록 없음, 즉시, 수수료 거의 0
3. 채널을 닫을 때 최종 잔액만 온체인에 1건 기록
```

중간에 상대가 옛 잔액으로 채널을 닫으려 하면, **페널티 트랜잭션**으로 예치금 전액을 뺏을 수 있다. 부정행위가 손해가 되도록 설계한 것 — **비트코인 본체와 똑같은 인센티브 논리**다.

## 11. 자주 하는 오해

| 오해 | 실제 |
|---|---|
| "비트코인은 익명이다" | 가명이다. 모든 거래가 영구 공개된다. 거래소 KYC로 주소가 신원에 한 번 연결되면 **과거 전체가 소급 추적**된다 |
| "채굴은 수학 문제를 푸는 것" | 무차별 대입이다. 지적 문제 해결이 아니라 **복권을 초당 수십조 번 긁는 것**에 가깝다 |
| "채굴자가 비트코인을 통제한다" | 규칙 검증 권한은 **노드**에 있다. 채굴자는 순서만 정한다 |
| "양자컴퓨터가 나오면 끝난다" | 위협 대상은 해시(SHA-256)가 아니라 **서명(ECDSA)** 이다. 게다가 공개키가 노출된 주소가 우선 위험하다. 양자내성 서명으로의 전환 논의가 진행 중이며 시간이 있다 |
| "2,100만 개니까 무조건 오른다" | 희소성은 필요조건일 뿐이다 → [[02-value-on-chain|02번 문서]] 1장 |
| "비트코인은 전기 낭비다" | 전기 소비가 **보안 그 자체**다. 다만 "그 보안이 그만한 가치가 있는가"는 별개의 정당한 논쟁이다 |

## 12. 요약

1. 비트코인의 발명은 암호 기술이 아니라 **인센티브 설계**다 — 정직이 공격보다 이득이 되게 만든 것
2. 소유권은 **256비트 개인키**로 증명된다. 2²⁵⁶은 우주 원자 수에 근접하는 크기라 추측이 불가능하다
3. 잔액이 아니라 **UTXO(안 쓴 수표) 목록**으로 관리된다. 온체인 지표 대부분이 이 구조 위에 세워져 있다
4. 채굴은 무차별 대입이고, **난이도 조정**이 10분 간격과 발행 스케줄을 지킨다
5. **2,100만 개**는 반감 규칙의 등비수열 합이다. 이미 95.5%가 발행됐다
6. 최종 권한은 채굴자가 아니라 **노드**에 있다
7. 파이널리티는 확률적이고, 6컨펌은 관행이다
8. 51% 공격으로도 **남의 코인을 훔치거나 없는 코인을 만들 수는 없다**
9. 최대 장기 과제는 **보안 예산** — 블록 보상이 0에 수렴할 때 수수료가 이를 대체할 수 있는가
