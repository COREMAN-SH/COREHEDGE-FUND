# 01. 블록체인이란 무엇인가

> 전제 지식 없음을 가정한다. 용어보다 **"어떤 문제를 풀려고 이렇게 만들었나"** 를 따라가는 순서로 쓴다.

---

## 1. 출발점: 돈은 원래부터 "기록"이다

지갑 속 현금을 떠올리면 돈이 물건처럼 느껴지지만, 현대 화폐의 대부분은 **기록(장부)** 이다.

당신이 친구에게 계좌이체 10만원을 보내면 실제로 일어나는 일은 이것뿐이다.

```
은행 장부:
  당신    5,000,000  →  4,900,000
  친구      300,000  →    400,000
```

돈이 물리적으로 이동하지 않는다. **은행이 관리하는 숫자 두 줄이 수정될 뿐이다.**

그래서 질문은 이렇게 바뀐다.

> **"이 장부를 누가 관리하는가?"**

지금까지의 답은 언제나 **신뢰받는 제3자(Trusted Third Party)** 였다. 은행, 카드사, 증권예탁원, 등기소. 이들이 장부를 독점 관리하고, 우리는 그들을 믿는다.

이 방식은 대체로 잘 작동한다. 다만 세 가지 전제가 필요하다.

1. 그 기관이 **정직**할 것
2. 그 기관이 **망하지 않을** 것
3. 그 기관이 당신의 접근을 **막지 않을** 것

이 셋 중 하나라도 깨지는 상황(2008년 금융위기, 자산 동결, 초인플레이션 국가의 은행)에서 "제3자 없이도 장부를 관리할 수 있는가"라는 질문이 나왔다.

---

## 2. 핵심 난관: 디지털 이중지불(Double Spending)

제3자를 없앤다고 하자. 각자가 장부 사본을 하나씩 갖는다. 즉시 문제가 생긴다.

**디지털 데이터는 완벽하게 복사된다.**

내가 "10코인을 A에게 보냄"이라는 메시지를 만들었다면, 같은 10코인으로 "10코인을 B에게 보냄"이라는 메시지도 동시에 만들 수 있다. 두 메시지 모두 내 서명이 붙어 있어 위조가 아니다. **둘 다 유효하다.**

A는 자기가 받았다고 믿고, B도 자기가 받았다고 믿는다. 장부가 갈라진다.

이것이 **이중지불 문제**다. 은행이 있으면 자동으로 해결된다 — 은행이 먼저 온 것만 처리하고 두 번째는 잔액 부족으로 거절한다. **은행은 "순서를 정하는 심판"** 이기 때문이다.

> **제3자를 없앤다는 것 = 심판 없이 순서를 합의해야 한다는 것**

블록체인이 실제로 발명한 것은 "디지털 화폐"가 아니라, **심판 없이 거래 순서에 합의하는 방법**이다. 이 한 문장이 블록체인의 전부라고 해도 크게 틀리지 않는다.

---

## 3. 도구 1: 해시 함수 — "봉인 스티커"

블록체인을 이해하려면 **해시(hash)** 하나는 정확히 알아야 한다. 어렵지 않다.

해시 함수는 **아무 길이의 데이터를 받아 고정 길이의 문자열을 뱉는 함수**다. 비트코인이 쓰는 SHA-256은 항상 **64자리 16진수**(256비트)를 만든다.

```
SHA-256("hello")
→ 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824

SHA-256("hellp")     ← 마지막 글자 하나만 바꿈
→ 7a2e1e5c6d3a3d0a5f4f5c1c9e2b7a4d8f1e3c6b9a2d5f8e1c4b7a0d3f6e9c2b
```

여기서 결정적인 성질 네 가지.

| 성질 | 의미 | 왜 중요한가 |
|---|---|---|
| **결정적** | 같은 입력 → 항상 같은 출력 | 누구나 같은 값을 재계산해 검증 가능 |
| **눈사태 효과** | 입력이 1비트만 달라도 출력이 완전히 달라짐 | 아주 작은 위조도 즉시 드러남 |
| **단방향** | 출력에서 입력을 역산할 수 없음 | 미리 답을 알아낼 수 없음 |
| **충돌 저항** | 같은 출력을 내는 다른 입력을 찾을 수 없음 | 다른 내용으로 바꿔치기 불가 |

**직관:** 해시는 **데이터의 지문**이다. 문서 1,000페이지든 한 글자든 지문은 64자리로 나온다. 지문이 같으면 내용이 같고, 내용이 한 글자라도 다르면 지문이 완전히 달라진다.

---

## 4. 도구 2: 블록을 체인으로 엮기

이제 거래들을 묶어 **블록**을 만든다. 블록 하나에는 이런 게 들어간다.

```
┌─────────────────────────────────┐
│  블록 #802                       │
│  ─────────────────────────────  │
│  이전 블록의 해시: 0000a3f9...   │  ← 여기가 핵심
│  거래 목록: [거래1, 거래2, ...]   │
│  시각: 2026-09-09 04:00          │
│  논스(nonce): 194837261          │
│  ─────────────────────────────  │
│  이 블록의 해시: 0000b7c2...     │
└─────────────────────────────────┘
```

각 블록이 **직전 블록의 해시를 자기 안에 품는다.** 이게 "체인"이다.

여기서 마법 같은 성질이 나온다. **500번 블록의 거래 하나를 조작하면:**

1. 500번 블록의 내용이 바뀜 → 500번의 해시가 완전히 달라짐
2. 501번 블록은 "500번의 해시"를 품고 있는데, 그 값이 이제 안 맞음 → 501번도 무효
3. 502번, 503번 … 최신 블록까지 **전부 다시 계산해야 함**

즉 **과거를 고치려면 그 이후 모든 블록을 다시 만들어야 한다.** 이것이 블록체인의 "변조 불가능성"의 정체다. 마법이 아니라 **연쇄 재계산 비용**이다.

---

## 5. 도구 3: 합의 — 누가 다음 블록을 쓰는가

체인으로 엮는 것만으로는 부족하다. 여전히 **"누가 다음 블록을 만들 권한을 갖는가"** 가 안 정해졌다. 아무나 만들 수 있으면 서로 다른 블록이 동시에 여러 개 나온다.

여기서 두 가지 주요 해법이 갈린다.

### 5-1. 작업증명 (PoW, Proof of Work) — 비트코인

**규칙:** 블록의 해시가 특정 조건(예: 앞자리가 0이 19개 이상)을 만족해야만 유효한 블록으로 인정한다.

해시는 역산이 불가능하므로, 조건을 만족시키는 유일한 방법은 **논스(nonce)라는 숫자를 바꿔가며 무차별 대입**하는 것뿐이다.

```
논스 = 1        → 해시 8f3a...  ✗
논스 = 2        → 해시 c71b...  ✗
논스 = 3        → 해시 2ae9...  ✗
        …  (수십조 번 반복)  …
논스 = 194837261 → 해시 0000000000000000000a3f9...  ✓ 성공!
```

이걸 **채굴(mining)** 이라 부른다. 여기서 중요한 비대칭이 있다.

> **찾기는 극도로 어렵지만, 검증은 즉시 된다.**
> 답을 찾는 데 전 세계 채굴기가 10분을 쓰지만, 그 답이 맞는지 확인하는 건 해시 한 번 계산이면 끝난다.

**왜 이게 보안이 되는가?** 과거를 조작하려면 그 이후 모든 블록의 논스를 다시 찾아야 하고, 그동안 정직한 네트워크는 계속 앞으로 나아간다. 따라잡으려면 **전체 연산력의 과반(51%)** 이 필요하다. 그 정도 하드웨어와 전기를 살 돈이면 정직하게 채굴해서 버는 게 더 이득이다.

**보안 = 경제적 비효율의 의도적 설계.** 비트코인이 전기를 많이 쓰는 건 부작용이 아니라 **보안 그 자체**다.

### 5-2. 지분증명 (PoS, Proof of Stake) — 이더리움 외 대부분

**규칙:** 자기 코인을 담보로 맡긴(스테이킹) 사람 중에서 블록 생성자를 뽑는다. 부정하게 행동하면 담보를 몰수(슬래싱)한다.

| | PoW | PoS |
|---|---|---|
| 비용의 원천 | 전기·하드웨어 (외부 비용) | 담보 코인 (내부 비용) |
| 공격 비용 | 연산력 과반 확보 | 스테이킹 물량 과반 매수 |
| 에너지 | 매우 높음 | 매우 낮음 |
| 공격 후 재공격 | 하드웨어가 남아 반복 가능 | 담보 몰수로 반복 어려움 |
| 비판 | 환경 부담 | "부자가 더 부자 되는" 구조, 담보 집중 |

> **함정:** "PoS가 PoW보다 우월하다"는 단순 비교는 성립하지 않는다. PoW의 보안은 **체인 외부의 실물 자원**(전기)에 뿌리를 두고, PoS의 보안은 **체인 내부 토큰 가치**에 뿌리를 둔다. 토큰 가격이 폭락하면 PoS 체인의 공격 비용도 같이 떨어진다. 순환 의존이 존재한다.

---

## 6. 그래서 블록체인은 정확히 무엇인가

지금까지의 조각을 하나로 합치면 정의가 나온다.

> **블록체인 = 중앙 관리자 없이, 참여자들이 동일한 거래 기록의 순서에 합의하고, 그 기록을 사후에 바꾸기 어렵게 만든 데이터 구조와 규칙의 묶음**

여기서 각 단어가 왜 붙었는지 되짚어보면:

| 구성 | 해결하는 문제 |
|---|---|
| 분산 사본 | 단일 기관 의존 제거 |
| 전자서명 | "이 거래를 정말 그 사람이 했는가" |
| 해시 체인 | "과거 기록이 바뀌지 않았는가" |
| 합의 규칙(PoW/PoS) | "누구의 버전이 진짜인가" (이중지불 해결) |
| 경제적 인센티브 | "왜 참여자들이 정직하게 행동하는가" |

---

## 7. 비용: 왜 느리고 비싼가

블록체인은 **일부러 비효율적으로 설계되어 있다.** 이유를 이해해야 한계도 이해된다.

일반 데이터베이스는 한 대의 서버가 한 번 처리하면 끝난다. 블록체인은 **전 세계 수천 대의 노드가 똑같은 계산을 중복 수행**한다. 성능이 아니라 **검증 가능성**을 사는 구조다.

숫자로 보면 체감된다.

| 시스템 | 초당 처리량(대략) |
|---|---|
| 비자(Visa) | 수만 건 |
| 비트코인 | 약 7건 |
| 이더리움 L1 | 약 15~30건 |
| 고성능 L1 (솔라나 등) | 수천 건 (설계 트레이드오프 존재) |

### 블록체인 트릴레마

**탈중앙성 · 보안 · 확장성** — 셋 중 둘까지만 쉽게 얻는다.

- 비트코인: 탈중앙성 + 보안 ↔ 확장성 포기
- 고성능 L1: 확장성 + 보안 ↔ 노드 하드웨어 요구가 높아 탈중앙성 약화
- 이더리움의 답: L1은 보안·탈중앙성에 집중하고, 처리(실행)는 **L2 롤업**에 위임

> 이 트릴레마는 코인 노트를 읽을 때 반복해서 등장한다. "이 체인은 무엇을 포기하고 무엇을 얻었나"가 기술 섹션의 핵심 질문이다.

## 8. 스마트컨트랙트 — 장부에서 컴퓨터로

비트코인의 장부는 "누가 얼마를 가졌나"만 기록한다. 이더리움은 여기에 **프로그램**을 올렸다.

**스마트컨트랙트**는 블록체인 위에 배포된 코드다. 조건이 충족되면 자동 실행되고, 아무도 중간에 막을 수 없다.

```
예: 간단한 에스크로 계약
  if (구매자가 대금을 입금했고 && 판매자가 물건 전달을 확인했으면)
      → 판매자에게 대금 자동 지급
  else if (30일이 지났는데 전달 확인이 없으면)
      → 구매자에게 자동 환불
```

**특징과 대가**

| 특징 | 이면의 대가 |
|---|---|
| 자동 실행, 중개자 불필요 | 버그도 자동 실행된다 |
| 코드가 공개되어 검증 가능 | 공격자도 코드를 읽는다 |
| 배포 후 변경 불가 | 취약점을 발견해도 못 고친다 |
| 누구나 호출 가능 | 악용도 누구나 가능 |

DeFi 해킹이 반복되는 근본 원인이 여기 있다. 은행이라면 "이상 거래 정지"를 누를 수 있지만, 스마트컨트랙트는 **설계된 대로 정확히 실행**된다. 설계가 틀렸어도.

> 코인 노트의 "실무 알림" 섹션에 오라클·플래시론·언더플로우 사고가 반복 등장하는 이유다.

## 9. 자주 하는 오해 정리

| 오해 | 실제 |
|---|---|
| "블록체인은 해킹이 불가능하다" | **체인 자체**의 과거 기록 변조가 어려울 뿐이다. 그 위의 스마트컨트랙트, 지갑, 거래소, 브릿지는 계속 털린다. 실제 손실의 대부분이 여기서 난다 |
| "블록체인은 익명이다" | **가명(pseudonymous)** 이다. 모든 거래가 영구 공개되고, 주소가 신원과 한 번 연결되면 과거 전체가 소급 추적된다. 오히려 현금보다 추적이 쉽다 |
| "탈중앙화되어 있으니 안전하다" | 탈중앙성은 정도의 문제다. 검증자 수, 지분 집중도, 클라이언트 다양성, 개발자 집중도를 각각 봐야 한다 |
| "온체인 데이터는 진실이다" | 체인에 **기록된 것**은 사실이다. 그러나 그 기록이 **무엇을 의미하는지**는 해석이다. 거래소 내부 이동을 "매도 압력"으로 읽는 건 해석이며 틀릴 수 있다 |
| "블록체인에 올리면 위조가 안 된다" | 체인은 **입력된 데이터가 바뀌지 않음**만 보장한다. 애초에 거짓 데이터를 넣으면 거짓이 영구 보존된다(**Garbage In, Garbage Forever**). 실물 연동에서 가장 큰 구멍 |

## 10. 요약

1. 돈은 장부다. 블록체인은 **관리자 없는 장부**를 만들려는 시도다
2. 관리자를 없애면 **이중지불**이 생기고, 이를 풀려면 **심판 없이 순서에 합의**해야 한다
3. **해시 체인**이 과거 변조를 어렵게 만들고, **합의 메커니즘(PoW/PoS)** 이 미래 기록의 권한을 정한다
4. 보안은 마법이 아니라 **경제적 비용**이다. 공격이 이득보다 비싸도록 설계한 것
5. 그 대가로 느리고 비싸다. **트릴레마**는 회피가 아니라 선택의 문제다
6. 스마트컨트랙트는 장부를 컴퓨터로 확장했고, 자동성과 불변성의 대가로 **버그도 불변**이 되었다
